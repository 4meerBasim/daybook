# Cloud sync (Supabase)

Status: shipped
Summary: Opt-in bidirectional cloud sync to a Supabase backend, built on the existing `updatedAt` / `deletedAt` columns, that no-ops cleanly whenever it is not configured, disabled, or offline.

## Details
Enabled from [[Settings]] under a "Cloud sync" group; scoped to the signed-in account's id (`auth.uid()`) — see [[Account sign-in (Google and Apple)]].

Client (`src/lib/supabase.ts`): creates the `@supabase/supabase-js` (v2.117) client ONLY when both `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` are present (read via `process.env`; Expo inlines `EXPO_PUBLIC_*` at build), otherwise exports `null`. `isSyncConfigured()` reports whether it exists. Auth sessions now persist: `storage: AsyncStorage`, `persistSession: true`, `autoRefreshToken: true` (refresh driven by `AppState` in `App.tsx`'s `AuthSync`). `react-native-url-polyfill/auto` is imported because supabase-js needs a WHATWG `URL` on React Native. `newShareCode()` backs [[Real-time shared lists (Supabase)]]; the old `newOwnerId()` anonymous stand-in was removed — the owner is the real `auth.uid()`.

Engine (`src/lib/sync.ts`): `syncNow()` iterates `SYNC_TABLES`, now covering tasks, projects, entries, journals, habits, subtasks, smart_lists, focus_sessions, attachments, and (newly added) task_state, task_tags, habit_sessions, entry_templates. Each table carries a `key: string[]` of its PK columns — most `['id']`, `task_state` `['taskId']`, `task_tags` `['taskId','tag']`. It pushes local rows with `updatedAt > lastSync` (mapping `updatedAt`→`updated_at`, `deletedAt`→`deleted_at`, adding `owner`) via `upsert(onConflict: key.join(','))`, then pulls remote rows for this owner changed since last sync and applies them locally newer-wins. It returns early (never throws) when supabase is `null`, the pref is off, or the owner id is missing (e.g. not signed in), and catches every error into a result object.

Local DB (`src/lib/db.ts`): two generic helpers — `getChangedRows(table, since)` and `applyRemoteRows(table, rows, keys = ['id'])` (quotes every identifier so reserved columns like `over`/`desc` are safe; builds `ON CONFLICT(<keys>) ... WHERE excluded.updatedAt > table.updatedAt` and assigns every non-key column, so composite-key tables like `task_state`/`task_tags` work). No local schema change: the `updatedAt`/`deletedAt` convention that every table already carries (see [[Persistence layer]]) is exactly what sync rides on. Prefs in the settings KV via the `JournalPrefs` pattern — `syncEnabled`, `syncOwnerId` (now the signed-in `auth.uid()`), `lastSyncAt`.

Store (`src/state/store.tsx`): `syncEnabled`/`setSyncEnabled`, `ensureOwnerId()`, `lastSyncAt`/`setLastSyncAt`, and a new `hydrate(snapshot)` that re-seeds every state slice — used to refresh the store after a pull. (The per-prefix id-sequence refs it used to re-seed were removed with the UUID migration — see below.)

Setup (`supabase/schema.sql`, `.env.example`): a documentation-only SQL file creates the synced tables (including the newly added `task_state`, `task_tags`, `habit_sessions`, `entry_templates`) plus the shared-list tables, each with `owner uuid` / `updated_at` / `deleted_at`, enables Row Level Security with `owner = auth.uid()` policies, and adds `tasks` to the realtime publication. Owner scoping is now backed by real Supabase Auth (Google / Apple ID tokens) — see [[Account sign-in (Google and Apple)]]; enable the providers in the Supabase dashboard. Not runtime-tested against a live project.

Globally-unique ids (resolved) — every user-created entity now gets a UUID instead of a sequential per-device id. `src/lib/id.ts` `newId()` wraps expo-crypto `randomUUID`; `src/state/store.tsx` calls it for tasks/projects/habits/subtasks/smart-lists/attachments/focus-sessions/journals/entries/templates (the old `${prefix}${seq}` scheme and `maxIdSeq` are gone). Seed/built-in entities keep their deterministic literal ids (`t*/u*/i*` tasks, `studio/work/home` projects, `default` journal, `tpl-*` templates, `h1` habit) — they are identical on every device, so sharing an id is correct, not a collision; the `ensureTask` seed-promotion check now uses the explicit `isSeedTaskId(id)` (`src/data/seed.ts`) instead of the old `startsWith('a')` prefix test. A one-time SQLite migration (`migrateIdsToUuid` in `src/lib/db.ts`, guarded by `user_version = 2`, run inside a transaction) rewrites every existing user-created local row to a UUID and remaps all by-convention foreign references consistently — `task_tags`/`task_state`/`subtasks`/`attachments`/`focus_sessions` taskId, `tasks.projectId` + `smart_lists.rules` projectId, `habit_sessions.habitId` and its composite `${habitId}:${startedAt}` id, `entries.journalId` + the `currentJournalId` setting, `entries.templateId`, `attachments.entryId` — and bumps `updatedAt` on changed rows so they re-push under their new ids. This removes the former newer-wins `ON CONFLICT(id)` collision risk in `applyRemoteRows` and `joinSharedList`. `supabase/schema.sql` id columns stay `text` (they correctly store both UUID strings and the literal seed ids). Resolves [[Phase 1 id counters collide after soft-delete]].
